- Randell spotted the middle line reading as crooked. Measuring it confirmed the cause: taken by eye off the source it sat 18.6 units from the outer upper-left edge at its lower end and 23.3 at its upper end, so the band widened as it rose.

Rebuilt as an offset 19 units along the edge normal, with the lower end run past the corner so it overlaps the square rather than floating beside it, and the upper end reaching further up, which also brings it nearer the sparkles as he asked.
- Re-rendered and re-applied to gid 34187113529446. 0 userErrors. Verified on the dev storefront.
- Worth remembering for the next composed icon: an interior edge that should be parallel to another edge must be *derived* from it, not measured separately off a grid. Eye-measured parallels drift by several units, which reads as crooked even when each endpoint looks right.
- Follow-up: Randell asked for the inner line further right again. Because the line is now derived rather than eyeballed, "further right" is a single number: the offset along the edge normal. Rendered 19, 22 and 25 side by side against the source and took 22, which matches the source's band proportion; 25 starts riding into the square. Re-applied to the same gid, verified on dev.
- Follow-up: the bar's top-right corner read as sharp. The outline was a plain polyline relying on the renderer's round line join, which only rounds by half the stroke width, far tighter than the front face's corners. Added `rpoly()` to `steel/bar.cjs`: it cuts each interior corner back by r and bridges it with a quadratic, clamped to half the shorter adjoining segment. Rendered r 5, 8 and 11 against the source and took **8**, the same radius as the front face; 11 loses the corner entirely. This rounds all three outline corners, which matches the source. Re-applied to the same gid and verified on dev.
- Follow-up: the far end still read as warped. Cause was the same class of error as the inner line: the right edge had been measured by eye at x 86 top and x 92 bottom, so it splayed outward as it descended. The far end is a face of the prism, so that edge must be vertical like the front face's. Set to a straight vertical at x 90 (which also brings the lower end in from 92, as Randell asked). Compared vertical at 90 with r8 and r6, and vertical at 87; took 90 with r8. Re-applied to the same gid, verified on dev.
- **Pattern across all three corrections to this icon:** every fault came from measuring a feature independently off the grid when it was geometrically constrained by another feature. Parallel edges, vertical edges and matching corner radii should be derived, not eyeballed. Worth applying to the next hand-built icon from the start.
- Follow-up: still warped. Measuring the three long lines found the cause: the upper-left silhouette and the inner line both ran at slope -1.020, but the lower-right silhouette ran at -1.219. On a prism those must be parallel. The far end was also only 27 tall against the front face's 42, so the two ends were not congruent.
- Rather than patch another edge, replaced the hand-measured builder with `steel/prism.cjs`, which takes **one front face and one axis vector** and derives everything: far face = front face translated, both long silhouette edges = the axis, inner line = the top face's far edge, corner radius shared. The shape cannot warp because no edge is independently specified. `steel/bar.cjs` deleted so there is one source of truth.
- Front and far faces are now both 37 x 42 and all three long lines share a slope. Re-applied to the same gid, verified on dev.

The first reference was itself loose, which is why every faithful reproduction of it looked warped.
- Built as `steel/prism2.cjs`. Three things measured (front face, axis direction, far-end position and size); everything that must agree with something else derived from them: the lower silhouette and the inner line both run along the axis, the far end's right edge is vertical, and the corners share one radius.
