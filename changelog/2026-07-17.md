- **Zipify OCU `InvalidStateError` (recurring)** — confirmed conflict: CreditsYard's `StoreCredit.getJSON` fetches `/cart.js?store-credit=1` with `responseType:'json'`; Zipify's extension reads `responseText` on the first `/cart.js` response guarding only against `blob` → throws. User confirmed CreditsYard stays (despite 0 `storcred*` redemption orders back to ≥ Jan 2025 via Admin GraphQL). Fix paths: vendor tickets (Zipify primary) + optional theme shim.

Reproduced 8/50 in Playwright probes. Console-noise-only impact (the app owns the gallery UI on PDPs).
- Added three null-guards to the `product-images` component in `assets/theme.js` (minified, hand-edited — NOT part of scripts/minify-assets.mjs pipeline) and `assets/theme.dev.js`, both folders (dev+live copies were hash-identical before and after): (1) `bindEventListeners` bails when `productMediaList` is null (the reported error); (2) `resetScrollPosition` same guard (would throw on mobile↔desktop resize); (3) variant-change `scrollTo` in the product section component same guard (would throw on variant switch). `node --check` passes on both files.
- User chose to KEEP the GG slider app (adds per-variant image filtering with Easy Variant Images; native Broadcast has thumbs-left/bottom + zoom + variant-scroll but no filtering). App has URL kill-switch `?pmslider-disable=1` for native-gallery comparison.
- Section status: `product-images` is rendered by the main product section — active on every product page (all PDP template variants). Live-store effect requires uploading the patched `assets/theme.js` to the published theme.
- **Verified live after user upload (theme now t/73):** all 3 guards present in the served theme.js; 50-run Playwright probe on the lip-liner PDP — 0 addEventListener errors (was 8/50 pre-guard), 0 InvalidStateError (CreditsYard shim still hooked 50/50), GG slider mounted 50/50, 0 load failures.
