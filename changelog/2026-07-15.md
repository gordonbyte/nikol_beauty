## bat.js (Bing UET) double-load re-verified on live (read-only, Playwright probe)
- Confirmed still present (07-15): bat.js loads TWICE on the live homepage — (1) main frame via GTM-PWZTLKXQ, which fired a pageview beacon `action/0?ti=187177478&tm=gtm002` (tm=gtm002 = GTM template), and (2) inside the Shopify web-pixels sandbox (custom/web-pixel-15 = "SS - Bing Conversion" custom pixel). Same UET tag 187177478, two pipelines → purchase-conversion double-count risk.
- Nuance: only the GTM copy beaconed on the homepage; the pixel copy loaded but stayed quiet (conversion-focused), so the overlap concentrates on checkout events.
- Recommended fix: keep the custom pixel (only sanctioned path into Shopify checkout events), pause/delete the UET tag inside GTM container GTM-PWZTLKXQ (user action in GTM admin), then re-run `scripts/probe-bing-uet.mjs` (new local probe, kept with the other probe-* tools) to confirm single load.
