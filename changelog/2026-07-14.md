# Changelog — 2026-07-14

## Hunted down the /wp-json/wc/store/v1/cart 404 (live, read-only investigation; fix applied by user in admin)
- Console 404 on every live page view: GET /wp-json/wc/store/v1/cart (a WooCommerce Store API route that doesn't exist on Shopify). DevTools blamed Shopify's Web Pixels sandbox file — misleading: the sandbox + Zipify OCU + Intelligems + Bugsnag all monkey-patch window.fetch, so the top stack frame is always a wrapper.
- Traced with headless Playwright + CDP full call stacks: real caller = **Microsoft 'Brand Agents' client** (adsagentclientafd-*.azurefd.net), injected on every page by the **Microsoft Clarity app's brandAgents_js app embed** (settings_data.json had both clarity_js and brandAgents_js enabled). Its chunk-i18n bundle literally contains fetch('/wp-json/wc/store/v1/cart') as a currency/country-detection fallback — WooCommerce-first code despite the feature being Shopify-only beta.
- Also ruled out along the way: theme files, all 20 first-level page scripts, second-level loaders, all 34 Klaviyo bundles, Microsoft UET bat.js + per-tag config (tag 187177478, signals all off), Clarity's own clarity.js, browser extensions.
- **Fix (user, live admin theme editor): disabled the 'Brand Agents' app embed only** — clarity_js (recordings/heatmaps) left ON. Error confirmed gone; saves ~365KB of Microsoft agent JS per page view.
- Side finding for later: bat.js (Bing UET) loads TWICE on live — once via the 'SS - Bing Conversion' custom pixel, once via a GTM container (GTM-PWZTLKXQ) — possible double-counted Bing conversions.
