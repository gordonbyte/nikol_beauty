## KAN-74 (backlog #11): Amount-off discount support in discount-sync — DECIDED: BUILD, and built

- Randell chose to build it (option 2) rather than dismiss.
- Design: per-ITEM amount-off (`appliesOnEachItem: true`) → per-variant effective percent = `floor(amount ÷ variant price × 100)`, capped at 100. **Floor, never round up** — the theme computes the displayed sale price from `promo_percent`, and the display must never undercut what checkout actually charges (display may be up to ~1% higher; checkout is the pleasant surprise). Sub-1% and unpriced variants skipped. Per-ORDER amount-off (`appliesOnEachItem: false`) stays unsupported — one order-level amount can't be honestly expressed as per-item percentages; admin UI badge now says so explicitly.
- Everything downstream unchanged: writer, tags (`promo-<n>` / `promo-up-to-<n>` — amount-off across differing variant prices naturally produces the up-to form), styling, conflict detection all operate on the converted percents.
- Files: `app/services/discounts.server.js` (query gains `appliesOnEachItem` + variant `price`; `supported` logic; `pctFor()` per-variant conversion in computeTargetState), `app/routes/app._index.jsx` (badges: per-order unsupported / per-item "% per variant"; badge preview shows `n` for varying percents), `PLAN.md` Phase 5 marked built.
- ESLint clean. NOT yet tested against a real amount-off discount — folded into the KAN-59 test matrix, which must run before the Aug 5 deploy (KAN-134). Uncommitted.

### Extension (same day): EXACT $ display, per Randell

Randell then chose full exact-price display over the %-approximation: amount-off promos must show **"$5 OFF"** badges and the **exact** sale price (price − amount), not a floored percent.

- **New theme pathway (3 snippets edited in `shopify-dev/`, pushed to dev theme #186425934130):**
  - `snippets/product-price.liquid`, `snippets/cart-bar.liquid`: per-variant metafield `custom.promo_amount` (dollars off; **precedence over `promo_percent`**) → sale = price − amount×100 cents, clamp 0; new single-variant tags parsed `promo-amt-<x>` / `promo-amt-up-to-<x>` (parse order amt-up-to → amt → up-to → promo, since `contains 'promo-'` matches the amt forms too); per-variant JSON map for variant-change recalc includes the amount path.
  - `snippets/product-grid-item.liquid`: amt tag parsing, badge `{n}` renders as `$<x>` with default wording `$<x> OFF` ("Up to" prefix preserved), slashed card price = price_min − amount, clamp 0.
- **New metafield definition (dev store):** `custom.promo_amount`, number_decimal, PRODUCTVARIANT, PUBLIC_READ — gid://shopify/MetafieldDefinition/230449316146.
- **App writer reworked (`sync.server.js`):** desired variant writes are now typed `{pct}` → `promo_percent` or `{amt}` → `promo_amount` (winning discount's value type decides; type switch sets new key + deletes old in one pass); AppliedState migrates legacy bare-number states on load; product tag form follows the winning discount's type, amount up-to uses the LARGEST dollar amount among amount-winning variants; clear path deletes both keys. `app._index.jsx`: amount badge preview now `$5 OFF` (default template `{n} OFF`), status badge "Amount-off — exact $ display".
- The percent effective-% conversion (floor) is retained INTERNALLY for winner selection/conflict math only — no longer user-visible for amount discounts.
