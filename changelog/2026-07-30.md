# Changelog — 2026-07-30

## KAN-42: "Show more" dead clicks on collection pages — root cause + dev-store fix

### Diagnosis
- The dead clicks Clarity reports are NOT a theme bug. 14 collection **descriptions** (agency SEO content) end with `<div class="show-more-content" style="display: none">…</div><button class="show-more">Read More</button>` — a pattern that requires JS the theme never had. The theme's only "show more" code (`[data-show-more]`) is the filter-sidebar "More options" expander, unrelated.
- Full sweep of all 131 dev-store collections: exactly **14 affected** — `makeup`, `new-arrivals`, `best-sellers`, `gifts`, `lips`, `lip-pencils`, `eyeliners`, `brows`, `gloss-and-liner`, `beauty-tools`, `concealers`, `face-primer`, `beauty-bundles`, `lip-balm`. (Also note: there is no `/collections/waterproof-eyeliners` — the eyeliner collection handle is `eyeliners`.)
- Collection pages: title is `<h1>`, description renders in `.collection-desc` at page bottom; the descriptions' `<h3>` headings skipped h2 (WCAG 1.3.1/2.4.6).

### Fix applied on the DEV store (descriptions, via Admin API — content edits, text 100% unchanged)
Structure-only transformation on all 14 descriptions:
1. `<div class="show-more-content" style="display:none">…</div><button class="show-more">Read More</button>` → `<details class="collection-desc__more"><summary><span class="more-label">Read More</span><span class="less-label">Read Less</span></summary>…</details>` (native disclosure: keyboard + screen-reader accessible with zero JS, indexable, cannot dead-click)
2. `<h3><strong>…</strong></h3>` → `<h2>…</h2>` (fixes heading hierarchy under the page h1; drops redundant strong)
3. Stripped Google-Docs paste junk: `<span>` wrappers, `dir="ltr"` attrs, stray `<meta charset="utf-8">`
4. Contact links made relative: `https://nikolbeauty.com/pages/about#contact` → `/pages/about#contact`
- Every word of visible/hidden text preserved verbatim (including pre-existing typos, deliberately).

### Fix applied in the theme — global snippet (final architecture, after iteration)
- First attempt put the CSS/script inline in `sections/collection.liquid`'s description block — but the dev store's collection template renders the description via a RICH-TEXT section (`index-rte`/`hero__rte`) under the title, not via collection.liquid's bottom `.collection-desc` (template JSONs differ per store). Section-scoped placement is therefore fragile.
- **Final:** NEW `snippets/custom-read-more-toggle.liquid` (style + idempotent fallback script, `data-sm-bound` guard) rendered globally from `layout/theme.liquid` just before the store-credit includes. Works wherever a collection description renders, on any template. `collection.liquid` reverted to stock.
- Style: summary as underlined link, default marker hidden, Read More/Read Less swap via `details[open]`, focus-visible outlines; legacy `button.show-more` styled to match. Script: legacy `.show-more` pattern gets a working toggle w/ aria-expanded; button hides itself if no hidden block. Inline snippet — NOT part of the minify pipeline.
